# SZH backend review and technical debt

Review date: 2026-11-09. Priority follows exposure and data integrity. P0 is a gate before release or network exposure. P1 affects a stable demo and integration. P2 is engineering maintenance debt.

| Priority / issue | Location and evidence | Impact | Suggestion and demo effect |
| --- | --- | --- | --- |
| P0 · Target repository visibility | The GitHub repository API returned public and an empty branch list. The first local prepare had no Git metadata | An upload would publish code and protocols | Recheck visibility and authorization after the team sets the repository to private. Affects code delivery, not a local demo |
| P0 · No access control | `main.mjs` binds loopback but allows any origin. No authentication, user scope, or quota. Task and run lists include history. Artifacts can be downloaded by id | If the port is forwarded or published, a caller who can connect can read data, submit compute, and cancel tasks. Local cross-origin access has no server origin allowlist | Keep the trusted local entry for demos. Implement auth, authorization, isolation, and rate limits before any multi-user or public opening. Block a public deployment |
| P1 · Dependency advisories | `package-lock.json`. That round of `npm audit --omit=dev` reported 198 affected package entries (190 high, 8 moderate, 0 critical) for 12 base advisories. High advisories come from undici and zod. The DSH dependency chain multiplies the count | Risk depends on the network, parse, and validation paths actually used. Reachability was not verified | Keep the lockfile. Assess a DSH and transitive upgrade, then regress. Recheck before an external demo. A trusted local acceptance can continue |
| P1 · Run status and cancel races | `cancel` in `solution-runs.mjs` only aborts and returns a temporary cancel_requested. A queued cancel waits for the head of the queue. Abort is not rechecked while files are collected, so the run can still succeed. An AIC spawn error can arrive before close. Descendant process exit was not verified | The user sees cancel accepted while the status is late or inconsistent. Partial files may remain | Define and persist the state transition. Wait for the process tree to exit, then commit the terminal state and artifacts. A cancel demo must cover the real executor |
| P1 · Run shutdown, timeout, and recovery | `close` in `main.mjs` closes TaskService and HTTP only. `RunService.perform` has no timeout. mkdir sits outside the try. There is no cross-process lock. The `.tmp` name is fixed. Create writes memory before disk | A crash or a long job can block the queue or leave a hanging state. Two processes on the same directory can overwrite each other. One invalid JSON file blocks startup | Add cancellable execution, a shutdown wait, rollback on write failure, and isolation of bad records. State a single-writer boundary. Affects a repeatable demo |
| P1 · No stages or live logs | `solution-runs.mjs` initializes `events` and never appends. AIC logs accumulate in memory and are written to execution.log only when the subprocess ends. A failed log has no artifact download | The client has only a snapshot and timestamps. Failure diagnosis needs the local directory | Emit ordered, replayable progress and logs from real runner events. The current demo uses a verifiable timeline and a terminal state |
| P1 · UI annotations conflict with validation | `solution-registry.mjs` uses strict:true at registration and strict:false at run time. Re-testing an inserted `x-advanced` returns invalid_schema. Output instances are not validated. `runtime.entrypoint` is only checked as a string. Adapter readiness is not checked | Real data cannot use some advanced fields from the mock. A successful registration does not mean the solution can run | Agree a ui_schema or a keyword allowlist. Use one validation mode for register and run. Add an adapter readiness check and structured errors. Demos with complex forms need this |
| P1 · Version and compute provenance | The registry locks the manifest file. `solution-runs.mjs` uses the machine's global Python and package path. It does not check code, dependencies, or model hashes per version. A fixed script starts on CPU. There is no remote dispatcher | Run configuration is traceable. The environment and assets can change. An AIC server and a laptop are not the same environment | Define version-bound code, weights, input assets, and an environment digest before building a remote runner. An AIC demo must pick a controlled runtime |
| P1 · Artifact storage boundary | `solution-runs.mjs` reads every top-level output into memory to hash it. Download reads the whole file the same way. There is no type, quota, lifecycle, or symlink constraint. Failures do not record a log | A large model file can exhaust memory or disk. A future untrusted generic executor could write an out-of-bounds reference | Limit the artifact directory and file types first. Hash and download as a stream. Separate diagnostic logs. Apply quota and retention. A large-artifact demo needs a check |
| P1 · Sandbox cleanup and credentials | `apps/szh-app/scripts/harness-sandbox.mjs` still allows `--fresh` to recursively delete the given directory, and chat still reads the private model configuration | The wrong argument can delete a directory. Sandbox chat can call a real model | Use a dedicated temporary directory and do not use `--fresh`. Later, only create a temporary directory and enable a networked model explicitly. Tests and demos should not share a data directory |
| P2 · Module and file constraints | `main.mjs` carries both APIs and the legacy static preview. Import still reads the old client sample allowlist. Archive entry depends on agreed paths. Unknown model-config fields have no single error | The backend is hard to move on its own. The old frontend build is coupled to the service | Keep the current routes and split a compatibility layer later. Move only after the directory contract is explicit. The current demo does not need that refactor |
| P2 · Request and document edges | Run idempotency compares JSON key order and scans the whole table. The GET version route also matches a trailing validate-input. Knowledge detail reuses a truncated search. A static file may write 200 before the file is read | Fingerprints, indexes, and error responses disagree on edge inputs | Add targeted regression next. Stabilize serialization and route matching. Handle a missing legacy static asset. This does not block the main path |
| P2 · Tests and processes | That review found no call that kills Node or Vite in bulk by process name or port. `dev-desktop.mjs` closes the Vite server and Electron child it created | Existing scripts did not reproduce the earlier bulk-kill problem. Real GPU or remote concurrency, crash-during-write, and process-tree regression are still missing | Keep process-ownership checks. Before production, verify a real runner disconnect, restart, and cancel. Do not treat stand-in tests as a deployment check |

## Smallest corrections in that round

- TaskService places DSH home in the selected data directory. The default path stays at var/dsh. Two tests that used to land in the project var now use the system temporary directory.
- The HTTP sandbox test reproduced a cancel that still waited when it arrived before sleep was registered. The sandbox delay now uses a Node timer that accepts AbortSignal. Production run status and cancel behavior were kept. The race is in the table above.
- The legacy AIC archive delivery link is injected from the process environment. When unset, the field is null. The real archive and the original link content stay in local materials.
- The release snapshot does not include specialist archives. Without authorized samples, the four legacy AIC tests are marked skipped. The original project still runs them when samples are present. An explicit sample path that is missing files is still an error.

## Commit safety check

- The scan covered the client-polish project, the paths intended for commit, and the local Git metadata that was reachable. The original project and its parent had no repository history. No nested repository or submodule was found. No existing remote branch was found. Other research projects, private-key directories, remote hosts, and installed dependency contents were outside this commit.
- The content to commit follows the allowlist. Real task, run, and DSH records, evaluation archives, personal and member deliveries, models and datasets, external PDFs, installed dependencies, screenshots, builds, client binaries, private connection scripts, and secret files are excluded. Original files stay in place. What remains are public source citations, contract samples in code, text test inputs, and old client source kept for compatibility tests.
- The text proposed for commit was searched for private-key markers, common credential formats, intranet locations, and account absolute paths. Extensions and file sizes were checked as well. Runtime materials and excluded binaries were not unpacked into the commit. No hit on a known pattern is not the same as a license review or a public review. MIT and OFL notices stay with the retained old frontend source. Redistribution rights for the external AIC implementation and model package need a separate confirmation.
- The remote was public on first inspection. The user owns the visibility change and the final push. Upload only after the user confirms that the code, license, and visibility meet the requirement.

## V0.1 build order

1. Confirm the manifest, UI annotations, version, and input-asset identifiers. Agree structured validation errors. Finish adapter capability and readiness checks.
2. Fix run status, idempotency, cancel, timeout, and restart recovery. Then define event sequence, stages, and terminal states. Frontend and backend agree what the user can do and which fields may be missing.
3. Fix artifact type, size, digest, provenance, download authorization, and retention. Verify large files and failure diagnosis.
4. Before remote AIC access, lock machine permissions, a trusted execution account, the environment, weights, and sample checksums. Define remote submit, query, cancel, artifact return, and disconnect recovery. Accept one controlled version and one case first.
5. A web demo only needs one real main path that can be rerun. Submit a fixed version from the actual Electron client, watch the real status, and download a checkable artifact. Also show one controlled failure. Model tuning, extra specialist models, and the full ecosystem are separate work.
